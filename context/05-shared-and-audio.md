# 05 — Shared components & audio

Cross-cutting pieces used by both Kana and Lessons (and Today, and the intro tour).
Almost every "these two screens look the same" observation in this app is literally one
type instantiated twice.

## Audio — `Pronouncer` + `Speech` (`nihongo/Pronouncer.swift`)

```swift
protocol Pronouncer {
    func speak(_ vocab: Vocab)
    func speak(kana: K)
    func stop()
}
```

Every "tap to hear" / auto-play path in the app calls through this seam, injected via
`.environment(\.pronouncer, ...)` from `nihongoApp.swift`. `SilentPronouncer` (no-op)
exists for previews/tests. The real implementation is `AudioPronouncer`.

### One speech policy, two players

There are **two** playback paths and they can't share a class: `AudioPronouncer` is
fire-and-forget, while `LessonPlayer` (Vocab List's "Play all") sequences a whole lesson
and needs `AVAudioPlayerDelegate`/`AVSpeechSynthesizerDelegate` callbacks to advance.
They *can* share the policy, and that's what kept drifting — both used to carry their own
copy of the voice lookup, the 0.4 rate and the `cleanWord` call, with nothing making them
agree. `enum Speech` now owns exactly that:

| Member | Owns |
|---|---|
| `Speech.locale` | `"ja-JP"` — the course's language, in one place |
| `Speech.utterance(_ text:)` | `cleanWord` the text, resolve the voice (`ja-JP`, else any installed voice whose language starts `ja`), set `rate = 0.4` |
| `Speech.clipPlayer(for: Vocab)` | An `AVAudioPlayer` primed on the word's bundled clip, or `nil` when it has none — volume and `prepareToPlay` included |

Callers that need completion callbacks set `delegate` on the returned player themselves;
that delegate is the *only* thing `LessonPlayer` adds over `AudioPronouncer`.

The playback order:

1. **Bundled clip first** — `Speech.clipPlayer` / `VocabStore.kanaAudioURL` resolve the
   pre-generated Kyoko `.m4a`. This is the primary path for 2087 of 2089 words and every
   kana cell: reliable, works in the simulator, no dependence on which voices a device
   has installed.
2. **Live TTS fallback** — for the 2 clip-less words and any bare kana glyph without a
   clip (shouldn't happen — see `DataTests.everyKanaHasABundledClip`),
   `AVSpeechSynthesizer` speaks `Speech.utterance(...)`. Every fallback logs
   `Track.audioMissing(_:)` — an Analytics event *and* a Crashlytics breadcrumb — so
   clip-coverage gaps surface in production instead of silently degrading
   (`08-analytics.md`).
3. **`PlaybackSession`** — a one-time, idempotent `AVAudioSession` activation
   (`.playback`, `.mixWithOthers`) shared by both paths. `.mixWithOthers` deliberately
   keeps the user's background music playing and lets words be heard with the silent
   switch on, instead of taking over system audio at launch.

`AudioPronouncer.speak(_:)` and `.speak(kana:)` both call `stop()` first, so a fast
sequence of taps replaces the current sound rather than layering.

Clips are generated by `scripts/build-minna-data.py` from the `minna` submodule's
`audio/` folder — macOS `say -v Kyoko`, produced upstream, **TTS and not native-speaker
recordings** (`01-data-model.md`).

> The file's top comment still says "Audio is deferred (v1), so the default
> implementation does nothing." That describes `SilentPronouncer`, not the app: audio
> ships, and `AudioPronouncer` is what's injected at launch.

## `CardOptionsBar` (`nihongo/Lessons/CardOptionsBar.swift`)

The field-visibility + sound toggle row shown on Learn and Today. Backed directly by
`@AppStorage` (`Pref.kanjiShown`/`.kanaShown`/`.romajiShown`/`.translationShown`/`.soundOn`)
so toggling instantly re-renders whatever card is showing — there's no intermediate
view-model layer to keep in sync. Each toggle logs `toggle_field` with the field name and
new state. The intro's first card teaches exactly these four fields, which is why it
deliberately picks a sample word that *has* a distinct kanji (`09-intro-and-survey.md`).

## Shared quiz/flashcard chrome (`nihongo/Components.swift`)

| Type | Used by | Note |
|---|---|---|
| `SoundToggle` | every quiz/practice toolbar | The single global sound flag — same `Pref.soundOn` as `CardOptionsBar`'s sound chip |
| `ScoreBadge` | Kana Classic/Listening, Kana Swipe, Kana Write, Train, Challenge | One right/wrong/total pill everywhere |
| `OptionGrid` + `QuizOptionButton` | Kana Classic/Listening, Challenge | The 2×2 multiple-choice grid, so both look identical |
| `SwipeOptionChip` | Train, Kana Swipe | The two candidates on a swipe-to-choose screen |
| `SwipeCard` | Today, Flashcards, Train, Kana Swipe, the intro | The card face itself: surface, hairline, shadow, "⟨ Swipe ⟩" hint, corner stamps, tilt-and-slide |
| `SwipeStamp` | via `SwipeCard` | The rotated corner stamp that previews a swipe's outcome |
| `CardStackPeek` | every swipeable screen | The decorative faded-deck backdrop |
| `choiceChip(_:)` (`View` ext.) | flashcard grade buttons, `SwipeOptionChip` | Tinted fill + coloured border, one chrome for every choice control |

`SwipeCard` is the piece that stopped four screens drifting: they had become four copies
of the same chrome with four different corner radii and three separate copies of the
stamp-opacity arithmetic. What stays with each caller is the part that genuinely differs —
the *meaning* of a swipe. Flashcards grade yourself, Train and the kana quiz pick an
answer, Today just turns the page (so it passes no stamps at all). Same gesture,
different verbs: the type owns the looks, the callers own the logic. The peek stack stays
*outside* `SwipeCard` on purpose — it must not move with the card, and Today drives
movement through `cardPager` rather than a drag binding.

`OptionGrid` rows are a **fixed 74pt** rather than expanding to fill: letting them grow
made the answers as large as the prompt, and on a quiz the question should dominate — the
options only need to be comfortably tappable.

### The two shrink-to-fit answer controls

Both hold *translations*, so both meet all 17 scripts, and both had their floors raised
from measurements over all 35 513 translations (full derivation in `07-ux-ui.md`):

- **`QuizOptionButton`** — `minimumScaleFactor(0.65)`, not 0.5. At 0.5 the worst glosses
  rendered at 8.5pt (Burmese) and 8.8pt (German, Vietnamese); 0.65 holds every language
  at ≥11.2pt. The price is 46 glosses that tail-truncate instead of shrinking rather than
  14 — 0.13% of the data instead of 0.04%. A clipped tail on a sentence-long gloss beats
  8pt text on all four buttons.
- **`SwipeOptionChip`** — `lineLimit(4)` and `minimumScaleFactor(0.6)`. It has a
  `minHeight` of 96 rather than a fixed height, so a long gloss is *allowed* to make it
  taller — but the old `lineLimit(3)` capped it before it could, and 0.4 of `.title3` is
  8pt. At `(3, 0.4)` the worst cases in en/fr/de/vi/my all bottomed out on that 8pt
  floor; `(4, 0.6)` never renders below 12pt and moves the tail-truncating share only
  from 0.08% to 0.16%.

Both also put the verdict in an **icon** as well as a colour (a corner badge on the
button, a chevron→check/cross swap on the chip), because red and green are the same
colour to roughly 8% of men — and on the button it's a corner badge specifically so
revealing the verdict doesn't reflow the label.

## `FlashDeck` + `FlashcardScreen` (`nihongo/Flashcards.swift`)

A generic, spaced-repetition-lite deck: `FlashDeck<Element>` shuffles once, swipe-right
("know it") retires a card, swipe-left ("don't know") sends it to the back of the deck to
resurface later; the deck is done when every card has been swiped right at least once.
`peek(_:)` exposes the next few cards purely so `CardStackPeek` can show the right number
of layers.

`FlashcardScreen<Element, Face>` is the whole shared screen — drag gesture, grade buttons,
top progress counter, auto-play, reveal button, and the congrats/restart screen — with
callers supplying only what's type-specific: the card face view, an id closure (for
auto-play-on-change detection), the speak closure, the reveal/summary labels, and an
optional `trackName` that becomes `"\(trackName)_grade"` / `"_done"` analytics events.
**Both Lessons Flashcards and Kana Flashcards are the same `FlashcardScreen` over
different element types** (`Vocab` vs `K`) — which is why they look and behave
identically.

There is **no trial-limit parameter or callback** on `FlashcardScreen` any more; gating
is a whole-lesson decision made once in `SelectModeView` (`06-monetization.md`).

The grade buttons double as swipe legends: arrows on the outer edges point the way to
swipe for each outcome, and they wear the same `choiceChip` chrome as the swipe quizzes'
option chips. An `animating` flag guards a double-grade mid-fling.

## `CardPager` (`nihongo/CardPager.swift`)

The horizontal swipe-to-turn-page gesture shared by Learn (ordered mode), Today and the
intro: drag with a slight rotation, fling off-screen past an **80pt** threshold, then the
next card re-enters from the opposite side. Forward flings *left*, like a page turn.

Three parameters, and the distinction between two of them is the interesting part:

| Parameter | Gates |
|---|---|
| `canPage: () -> Bool` | **Whether the page may turn at all** — checked inside `commit`, so it also blocks a programmatic fling. Today passes `{ picks.count > 1 }`: a one-card deck has nowhere to go. |
| `draggable: Bool` | **Whether a drag turns the page.** For a screen that pages by button only but still wants the fling animation. |
| `fling: Binding<Int?>` | Trigger the same animated transition programmatically — Learn's Random button sets it to `1`. |

`draggable` exists because `canPage` **couldn't express it**: `canPage` gates `commit`,
so using it to disable dragging would refuse the programmatic fling along with the
gesture. The intro pages by button only and needs the animation, which is what forced the
split. A re-entrancy guard (`animating`) ignores a swipe started mid-animation.

## Localization split — two independent languages

There are deliberately **two separate language settings**, both `@AppStorage` and both
offering the same **17** codes:

- `Pref.appLanguage` — the app's own UI text (tab labels, buttons, screen titles),
  resolved through `L.t(_:)` (`nihongo/Localization.swift`) against the bundled
  `UIStrings.json` (136 keys × 17 languages). Falls back English → the key itself if a
  translation is missing, which is why `LocalizationTests` checks key parity and format
  placeholders rather than trusting the compiler. `RootView` keys its whole tree on
  `.id(appLanguage)` so switching it rebuilds the UI instantly instead of needing a
  relaunch.
- `Pref.translationLanguage` — which language Japanese vocabulary is translated *into*
  (vocab lists, flashcards, Train, Challenge, search). Resolved per-lesson via
  `VocabStore.lesson(_:_:)`, and re-resolved on push by `SelectModeView`/`VocabListView`
  so changing it mid-session takes effect on the next screen entry.

They can differ freely (UI in English, meanings in French) — this mirrors the RN app's
separation of interface language from study-content language. `L.deviceDefault` picks the
device language when it's one of the 17, mapping any Chinese device language to
`zh-Hant`, and is now the first-launch default for **both** settings.

Two consequences of `L.t`'s fallback worth remembering: a typo in a key renders as
English-looking text that no translation pass will ever cover (hence
`IntroTests.introStringsHaveEnglishEntries`), and every string goes through
`String(format:)`, so a literal `%` must be written `%%`
(`LocalizationTests.literalPercentSignsAreEscaped`). Run the `check-i18n-parity` skill
after any string change.

## `LegalView` (`nihongo/Legal/LegalView.swift`)

Renders a bundled `.txt` in a plain scrollable, text-selectable sheet, chosen by
`LegalDoc`: `PrivacyPolicy`, `TermsOfUse`, and `KanjiStrokeOrders-LICENSE` (the BSD
notice the bundled font requires shipping). Used from both `SettingsView` and
`PaywallView` — the paywall must surface the subscription terms plus these links for App
Review. `LegalTests` only pins that the two policy files are bundled and non-trivial,
which is the part a build can silently drop.
